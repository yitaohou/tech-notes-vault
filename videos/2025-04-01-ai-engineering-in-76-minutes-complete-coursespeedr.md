# AI Engineering in 76 Minutes (Complete Course/Speedrun!)

摘要: [[2025-04-01-ai-engineering-in-76-minutes-complete-coursespeedr-summary|完整摘要]]

## 知识点

- [[active-learning]] — 当拥有的数据量超过计算预算所能承受的范围时，可用active learning挑选出最有帮助的样本子集，而不是使用全部数据。（[57:04](https://youtu.be/JV3pL1_mn2M?t=3424)）
- [[adapter-multi-variant-serving]] — adapter 方法可以让多个微调变体共享同一个 base model 进行服务，因此需要提前规划究竟需要多少个微调模型。（[51:04](https://youtu.be/JV3pL1_mn2M?t=3064)）
- [[agent-compounding-error-risk]] — 相比更简单的 AI 应用，agent 通常需要更强大的模型，因为完成任务往往需要多个步骤，每增加一步都会因为复合误差（compounding errors）而降低整体成功率，且由于 agent 能访问强大的工具，出错的风险和代价也更高。（[36:03](https://youtu.be/JV3pL1_mn2M?t=2163)）
- [[agent-definition]] — 在最广泛的定义下，agent 是任何能感知环境并对环境采取行动的东西；对 AI 系统而言，这意味着模型能观察环境、基于观察做出决策、采取影响环境的行动，并从行动结果中学习。（[36:03](https://youtu.be/JV3pL1_mn2M?t=2163)）
- [[agent-efficiency-metrics]] — 评估 agent 效率的指标包括完成任务平均所需步骤数、完成任务的成本、每个动作的平均耗时、是否存在特别慢或昂贵的动作，以及与基线（如另一个 agent 或人类）的对比表现。（[39:04](https://youtu.be/JV3pL1_mn2M?t=2344)）
- [[agent-environment]] — Agent 的环境由具体使用场景定义：对于 game playing agent，游戏本身就是它的环境；对于 web scraping agent，互联网就是它的环境。（[36:03](https://youtu.be/JV3pL1_mn2M?t=2163)）
- [[agent-memory-hierarchy]] — 对所有任务都必需的信息应该通过训练直接写入模型权重，很少用到的信息应放在长期记忆（如 RAG）中，而当前会话的即时上下文信息则属于短期记忆。（[42:04](https://youtu.be/JV3pL1_mn2M?t=2524)）
- [[agent-memory-mechanisms]] — agent 通常具备三种主要记忆机制：一是通过训练内嵌在模型本身的 internal knowledge，二是 context window；第三种机制在本段结尾处被截断，留待下文展开。（[39:04](https://youtu.be/JV3pL1_mn2M?t=2344)）
- [[agent-memory-system]] — agent 面临的一大核心挑战是如何随时间记住信息，memory system 让模型能够跨多次交互保留并利用信息。（[39:04](https://youtu.be/JV3pL1_mn2M?t=2344)）
- [[agent-multi-step-reasoning-loop]] — 以预测未来三个月销售收入为例，agent 会先推理如何完成任务，生成 SQL 查询获取历史销售数据，执行查询后分析信息是否充分，必要时再生成并执行额外查询，最后基于收集到的数据做出预测并判断任务已完成。（[36:03](https://youtu.be/JV3pL1_mn2M?t=2163)）
- [[agent-planning-failure-types]] — agent 规划阶段可能出现的失败类型包括：使用无效工具、使用有效工具但参数无效、使用有效工具但参数值不正确，以及未能达成目标或满足约束。（[39:04](https://youtu.be/JV3pL1_mn2M?t=2344)）
- [[agent-safety-oversight]] — agent 系统的能力越强，就越需要谨慎考虑安全性、安全防护与伦理使用问题，确保其始终在合适边界内运行并接受适当监督。（[42:04](https://youtu.be/JV3pL1_mn2M?t=2524)）
- [[agent-system-four-pillars]] — 通过组合 RAG 获取信息、工具扩展能力、规划处理复杂任务、记忆系统保持连续性，agent 可以逐步应对日益复杂的问题。（[42:04](https://youtu.be/JV3pL1_mn2M?t=2524)）
- [[agent-tool-failure-types]] — agent 除了规划失败外，还可能出现 tool failure，包括高层计划到具体函数名的翻译错误、无法访问所需工具，或工具返回错误结果（如生成质量差的 SQL 查询）。（[39:04](https://youtu.be/JV3pL1_mn2M?t=2344)）
- [[agent-tools-power]] — 使 agent 强大的关键在于它所能调用的工具集合，例如 ChatGPT 作为一个 agent，可以搜索网页、执行 Python 代码、生成图像等多种能力都来自于它所配备的工具。（[36:03](https://youtu.be/JV3pL1_mn2M?t=2163)）
- [[agentic-pattern]] — 为模型提供所需信息主要有两种主流模式：RAG 让模型从外部数据源检索相关信息，agentic pattern 让模型主动使用网页搜索、API 等工具去获取信息。（[30:02](https://youtu.be/JV3pL1_mn2M?t=1802)）
- [[agentic-write-actions]] — write actions（如发邮件、下单、转账）会让 agent 系统直接改变外部环境状态，因此比只读操作风险大得多，实施时需要额外的谨慎和安全防护。（[72:08](https://youtu.be/JV3pL1_mn2M?t=4328)）
- [[ai-accelerator]] — GPU 是目前推理领域最主流的 accelerator 类型，专用 AI 芯片的普及度也在持续上升。（[63:05](https://youtu.be/JV3pL1_mn2M?t=3785)）
- [[ai-app-architecture-maturity-stages]] — 随着需求变复杂，AI应用架构通常依次演进：先加强上下文构建，再加guardrails防护，接着引入model routing与gateway，然后用caching做性能与成本优化，最后加入复杂逻辑与写操作。（[69:07](https://youtu.be/JV3pL1_mn2M?t=4147)）
- [[ai-assisted-prompt-writing]] — 除了人工或自动化工具，也可以直接用 AI 模型本身来撰写和改进提示词。（[27:02](https://youtu.be/JV3pL1_mn2M?t=1622)）
- [[ai-engineering]] — AI engineering 近年快速兴起的两个原因是：AI 模型解决实际问题的能力大幅提升，同时基于这些模型进行开发的门槛大幅降低。（[00:00](https://youtu.be/JV3pL1_mn2M?t=0)）
- [[ai-evaluation-importance]] — evaluation 是 AI engineering 中至关重要却常被低估的环节，对某些应用而言可能消耗开发工作的大部分精力，是规避风险、发现机会、定位系统失效之处的关键手段。（[06:00](https://youtu.be/JV3pL1_mn2M?t=360)）
- [[ai-generated-content-training-degradation]] — 当高质量人类数据枯竭后模型被迫用 AI 生成内容训练，存在导致性能退化的潜在风险。（[06:00](https://youtu.be/JV3pL1_mn2M?t=360)）
- [[ai-generated-data-quality-check]] — 由于人类标注本身并不总能保持一致性，用AI生成数据是提升数据质量的一种选择，但必须像检查人工数据一样测量其质量。（[57:04](https://youtu.be/JV3pL1_mn2M?t=3424)）
- [[ai-judge-bias]] — AI judge 存在三种常见偏见：self bias（偏好来自同一模型的回答）、position bias（偏好比较中排在前面的答案）、verbosity bias（偏好更长的回答）。（[12:01](https://youtu.be/JV3pL1_mn2M?t=721)）
- [[ai-judge-classification-vs-scoring]] — 由于语言模型普遍更擅长处理文本而非数字，AI judge 在分类任务（如判断类别）上的表现通常优于数值评分任务。（[12:01](https://youtu.be/JV3pL1_mn2M?t=721)）
- [[ai-judge-limitations]] — AI judge 本质上是概率性的，同一个 judge 面对相同输入，如果提示词不同或仅重新运行一次，也可能给出不同的评分，这使评估结果难以复现或信赖。（[12:01](https://youtu.be/JV3pL1_mn2M?t=721)）
- [[ai-judge-prompt-design]] — 为 AI judge 设计提示词时需要包含评估任务（task）、评判标准（criteria）和评分体系（scoring system）。（[12:01](https://youtu.be/JV3pL1_mn2M?t=721)）
- [[ai-orchestrator-tools]] — 当应用涉及多个模型、数据源和工具，交互变得复杂时，orchestrator（如 LangChain、LlamaIndex、Flowise、LangFlow、Haystack）可以帮助管理这些组件如何协同工作。（[72:08](https://youtu.be/JV3pL1_mn2M?t=4328)）
- [[ai-system-monitoring]] — monitoring 只能告诉你系统出了问题（例如「车坏了」），但不能告诉你问题出在哪里；它追踪的是外部输出，而非内部状态。（[72:08](https://youtu.be/JV3pL1_mn2M?t=4328)）
- [[ai-system-observability]] — observability 相当于给系统的每个部分都装上传感器，出问题时能精确定位具体是哪个环节失效，而不只是知道出了问题。（[72:08](https://youtu.be/JV3pL1_mn2M?t=4328)）
- [[ai-training-vs-inference]] — AI 模型的生命周期分为 training 和 inference 两个阶段：training 负责构建模型，inference 负责在生产环境中用模型对给定输入计算输出。（[60:04](https://youtu.be/JV3pL1_mn2M?t=3604)）
- [[annotation-guideline-clarity]] — 标注指南必须明确定义什么是好回答，例如一个回答能否是正确但不够有帮助、评分3分与4分的区别是什么，这类标准对人工和AI标注同样至关重要。（[57:04](https://youtu.be/JV3pL1_mn2M?t=3424)）
- [[anomaly-detection-prompts]] — 使用 anomaly detection 来识别异常的提示词，是发现潜在攻击行为的一种防御策略。（[27:02](https://youtu.be/JV3pL1_mn2M?t=1622)）
- [[api-provider-control-risk]] — 使用第三方 API 存在控制权风险：需要考虑如果 API 提供商倒闭、修改服务条款，或在某些地区被禁用，应用该如何应对。（[18:01](https://youtu.be/JV3pL1_mn2M?t=1081)）
- [[api-provider-functionality-restriction]] — 使用第三方 API 会把应用限制在该提供商所提供的功能范围内，例如可能无法 fine-tune 模型，也无法获取 log probabilities。（[18:01](https://youtu.be/JV3pL1_mn2M?t=1081)）
- [[approximate-nearest-neighbor-search]] — 向量搜索本质上是一个 K nearest neighbor 搜索问题，但在大数据集上精确 KNN 计算开销过高，实践中常改用 approximate nearest neighbors 算法。（[33:02](https://youtu.be/JV3pL1_mn2M?t=1982)）
- [[architecture-simplicity-reliability]] — 对于某些应用场景，一个组件更少的简单架构比塞满各种功能的复杂架构更可靠、更容易维护。（[75:08](https://youtu.be/JV3pL1_mn2M?t=4508)）
- [[attention-mechanism]] — attention 机制让模型在生成每个输出 token 时可以参考输入的任意位置，相当于回答问题时可以随时翻阅书中任意一页，而不只是依赖摘要。（[03:00](https://youtu.be/JV3pL1_mn2M?t=180)）
- [[attention-mechanism-optimization]] — attention mechanism optimization 专门用于提升 Transformer 模型 attention 计算的效率，因为该计算过程通常非常消耗内存。（[66:06](https://youtu.be/JV3pL1_mn2M?t=3966)）
- [[attention-score-computation]] — 模型通过比较 Q 向量和 K 向量的相似度来决定给每个输入 token 分配多少注意力，相似度越高，该 token 对应的 V 向量对输出的影响就越大。（[03:00](https://youtu.be/JV3pL1_mn2M?t=180)）
- [[automated-prompt-engineering-tools]] — 自动化提示词工程工具（如 open prompt、DSPy）让用户指定输入输出格式、评估指标和评估数据后，自动执行类似 automl 的过程寻找最优提示词。（[27:02](https://youtu.be/JV3pL1_mn2M?t=1622)）
- [[automated-prompt-tool-limitations]] — 自动化提示词工具如果底层要发起大量 API 调用会很贵，还可能生成带 typo 或其他问题的提示词，并且未必能跟上模型需求的变化，因此建议先做 manual prompt engineering，再考虑引入自动化工具。（[27:02](https://youtu.be/JV3pL1_mn2M?t=1622)）
- [[autoregressive-generation-bottleneck]] — 语言模型的自回归特性使其必须逐个 token 顺序生成文本，这构成了推理速度的顺序性瓶颈，多种技术专门用于缓解这一限制。（[63:05](https://youtu.be/JV3pL1_mn2M?t=3785)）
- [[autoregressive-inference-memory-bound]] — 自回归语言模型（autoregressive LLM）的 inference 通常属于 memory bandwidth bound，而非 compute bound。（[60:04](https://youtu.be/JV3pL1_mn2M?t=3604)）
- [[backpropagation]] — 神经网络训练通常使用 backpropagation：每个训练步骤包含前向传播（forward pass，根据输入计算输出）和反向传播（backward pass，根据前向传播的信号更新模型权重）。（[45:04](https://youtu.be/JV3pL1_mn2M?t=2704)）
- [[base-model-capability-data-requirement]] — base model 越强大、越接近期望性能，微调所需的样本数量就越少。（[54:04](https://youtu.be/JV3pL1_mn2M?t=3244)）
- [[batch-inference-api]] — batch inference API 针对成本优化，把多个请求合并一起高效处理，但延迟更高，适合定期生成报告、合成数据等没有严格响应时间要求的场景。（[60:04](https://youtu.be/JV3pL1_mn2M?t=3604)）
- [[batch-size-fine-tuning-hyperparameter]] — 较大的 batch size 能加快样本处理速度但需要更多显存，过小的 batch size 会导致训练不稳定。（[51:04](https://youtu.be/JV3pL1_mn2M?t=3064)）
- [[benchmark-saturation]] — 公开评估基准很容易被饱和，即模型达到满分，昨天还很有挑战性的测试今天就变成了简单练习。（[09:01](https://youtu.be/JV3pL1_mn2M?t=541)）
- [[benchmark-selection-for-model-narrowing]] — 公开 benchmark 的正确用法是先筛出一小部分候选模型，再用自己的 benchmark 和指标做更严格的测试，因为公开 benchmark 很少能完美代表你的应用需求。（[18:01](https://youtu.be/JV3pL1_mn2M?t=1081)）
- [[best-of-n-sampling]] — 部分公司完全跳过强化学习步骤，改用 best-of-N 策略：生成多个输出后挑选 reward model 评分最高的结果。（[06:00](https://youtu.be/JV3pL1_mn2M?t=360)）
- [[bootstrap-evaluation-reliability-test]] — 可以对评估集做多个 bootstrap 抽样，若不同抽样结果差异很大（例如一次 90% 一次 70%），说明该评估流程不可信。（[21:01](https://youtu.be/JV3pL1_mn2M?t=1261)）
- [[bottleneck-specific-optimization]] — compute bound workload 更适合用算力更强的芯片或把任务分布到多颗芯片上来优化，而 memory bandwidth bound workload 更适合用内存带宽更高的芯片来优化。（[60:04](https://youtu.be/JV3pL1_mn2M?t=3604)）
- [[cache-eviction-policy]] — 随着规模扩大，需要设置eviction policy（如least recently used或least frequently used）来管理缓存大小。（[69:07](https://youtu.be/JV3pL1_mn2M?t=4147)）
- [[cache-storage-implementation-options]] — 缓存实现方案范围从速度快但容量有限的in-memory storage，到Postgres SQL、Redis这类数据库，需按需求权衡速度与容量。（[69:07](https://youtu.be/JV3pL1_mn2M?t=4147)）
- [[capability-discovery-evaluation]] — 对于通用模型，评估不能只覆盖已知任务，还需要去发现模型可能具备的、甚至超出人类能力范围的新能力。（[09:01](https://youtu.be/JV3pL1_mn2M?t=541)）
- [[capability-extension-tools]] — Agent 工具的第二大类是 capability extension tools，用于弥补模型自身能力短板，例如计算器（因为 AI 模型常常不擅长复杂数学运算）、时区或单位转换器、翻译服务，以及代码解释器（code interpreter）。（[36:03](https://youtu.be/JV3pL1_mn2M?t=2163)）
- [[catastrophic-forgetting]] — sequential fine-tuning（先训练任务 A、再训练任务 B）可能导致 catastrophic forgetting，即模型在学习任务 B 后丧失在任务 A 上的能力。（[48:04](https://youtu.be/JV3pL1_mn2M?t=2884)）
- [[chain-of-thought-prompting]] — Chain of Thought prompting 通过让模型显式「think this through step by step」来提升推理表现，是给模型思考时间的方法之一。（[27:02](https://youtu.be/JV3pL1_mn2M?t=1622)）
- [[chat-template-mismatch]] — system prompt 与 user prompt 的组合模板因模型和版本而异，若使用错误模板（哪怕只是多了一个换行符）都可能引发难以察觉的性能异常（silent failure），使用第三方工具构建 prompt 时尤其要严格遵循模型的 chat template。（[24:02](https://youtu.be/JV3pL1_mn2M?t=1442)）
- [[chinchilla-scaling-law]] — Chinchilla scaling law 建议训练 token 数量应约为模型参数量的 20 倍，例如一个 30 亿参数的模型大约需要 600 亿训练 token。（[03:00](https://youtu.be/JV3pL1_mn2M?t=180)）
- [[chunk-context-augmentation]] — 每个 chunk 可以附加元数据（如标签、关键词）来增强可检索性，例如电商场景中可以附加商品描述和评论信息。（[33:02](https://youtu.be/JV3pL1_mn2M?t=1982)）
- [[chunk-overlap]] — chunk 之间设置重叠（overlap）可以避免跨越 chunk 边界的重要信息被切断丢失。（[33:02](https://youtu.be/JV3pL1_mn2M?t=1982)）
- [[chunk-size-tradeoff]] — 更小的 chunk size 能让模型 context 中容纳更多样化的信息片段，但可能丢失重要上下文，且会增加计算开销（尤其是 embedding-based retrieval）。（[33:02](https://youtu.be/JV3pL1_mn2M?t=1982)）
- [[clear-explicit-instructions-strategy]] — 有效 prompt engineering 的第一个策略是写清晰明确的指令，例如让模型给作文打分时，需要说明具体评分标准、是否允许打小数分、无法判断时该如何处理等细节，以减少歧义。（[24:02](https://youtu.be/JV3pL1_mn2M?t=1442)）
- [[commercial-api-additional-capabilities]] — 商业 API 通常自带开箱即用的额外能力，例如可扩展性（scalability）、function calling（访问外部工具）、结构化输出（structured outputs）和输出防护栏（output guardrails），这些自行实现起来往往颇具挑战。（[18:01](https://youtu.be/JV3pL1_mn2M?t=1081)）
- [[comparative-evaluation]] — comparative evaluation 是直接比较不同模型的输出结果，从而判断哪个模型更适合当前用例。（[15:01](https://youtu.be/JV3pL1_mn2M?t=901)）
